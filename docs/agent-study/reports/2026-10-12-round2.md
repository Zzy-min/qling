## 1. Hooks

### Grok Build（`crates/codegen/xai-grok-hooks/`，~13.7k 行）
- `src/event.rs` `HookEventName`：SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / PostToolUseFailure / PermissionDenied / Stop / StopFailure / StopCancelled / Notification / SubagentStart / SubagentStop / PreCompact / PostCompact / SessionEnd；每个事件带 `EventTraits{gate: GateKind, matcher: MatcherPolicy, hub_forward}`。别名兼容（`beforeShellExecution`、`afterFileEdit` 等）。
- `GateKind`：Observe / Tool / Stop / PostTool / Prompt——区分"只观察"与"可拦截"。Prompt gate 的 block reason 只给用户、不进模型上下文（注释第 186–190 行）。
- `truncate_payload`（event.rs:617）：序列化 > `MAX_PAYLOAD_SIZE` 时按字符边界截断并加 `[truncated]`。
- `src/matcher.rs` `HookMatcher::new(pattern)` 正则匹配工具名；`matcher_allows`。
- `src/dispatcher.rs`：`dispatch_pre_tool_use` 返回 `PreToolUseResult{decision, updated_input: InputRewrite, additional_context}`；`dispatch_stop` + `StopDispatchResult::wants_continuation/feedback`（Stop hook 可要求继续）；`dispatch_sequential_gate` 注释"hook 出错 fail-open，只有健康的 deny 才拦截"。
- `src/trust.rs`：`Trust::allows_project_sources`（项目级 hooks/插件仅在受信工作区加载）；`DisabledHooks`（`$GROK_HOME/disabled-hooks` + `allow_managed_hooks_only`）、`disable_hook/enable_hook`。

### qling 现状
- `src/hooks/json-hooks.ts`（197 行）：事件仅 5 个（SessionStart/SessionEnd/PreToolUse/PostToolUse/PostToolUseFailure）；**无 matcher**，每个 PreToolUse 命令对所有工具都 spawn；失败/非法 JSON → `ask`（fail-closed，比 Grok 保守，合理）；stdout/stderr 有 `byteLimited`，但**stdin payload（`context.arguments` 全量）不设上限**；审计写 `hooks/events.jsonl`。
- 需 `QLING_JSON_HOOKS_ENABLED=true`；manifest 单一来源（`stateDir/hooks.json` 或 env），无项目级/信任区分。
- `src/types.ts:143` `HookResult` 已有 `updatedInput` / `preventContinuation` / `additionalContexts` 字段，但 JSON hook 解析后整体透传，未校验 `updatedInput` 形状。
- `src/agent-loop.ts:461` 每个 `AgentLoop.init()` 都 `installJsonHooks` 并触发 `SessionStart`——子 agent 也会（见 §3）。

### 可借鉴
1. **matcher 字段**（中/低）：`{command, args, matcher?: "^(bash|write|mcp__.*)$"}`，不匹配直接跳过 spawn。减少每次工具调用的进程开销。
2. **Stop / PreCompact / UserPromptSubmit 事件**（中/中）：Stop hook 可返回 `{continue:true, feedback}` 实现"未跑测试不许停"（对应 Grok `dispatch_stop`）；PreCompact 可与第 1 轮压缩落盘配合。
3. **payload 上限**（低成本必做）：stdin JSON 超过 `QLING_JSON_HOOKS_MAX_PAYLOAD_BYTES` 截断并标记。
4. 子 agent 不应重复触发 SessionStart（并入 Brief 05）。

## 2. MCP（含 mcp_truncate）

### Grok Build
- `crates/codegen/xai-grok-tools/src/util/mcp_truncate.rs`：
  - `MCP_MAX_OUTPUT_BYTES=20_000`；`mcp_max_output_bytes()` 优先级 host 设定 > env（`GROK_MAX_MCP_OUTPUT_BYTES` > `MAX_MCP_OUTPUT_BYTES`）> 默认；`types/context.rs` `mcp_max_output_bytes_for`：per-tool > MCP 专用 > 全局默认，**MCP 覆盖不外溢到非 MCP 工具**。
  - `truncate_mcp_text`：超限时把**全文写到会话目录 `mcp/<sanitized call_id>.json|txt`**，内联保留前缀并追加 `[MCP output truncated: showing first X of Y. Full output written to: <path>. …]`。
  - `McpDumpKind::classify`：JSON/长行(>2000B) 分类，`steer()` 告诉模型"长行 JSON 用 shell+jq 查询，grep/read_file 无效"。
  - `sanitized_stem` 防 `call_id` 路径穿越；先抽取 data-URI 图片再截断（测试 `mcp_data_uri_image_survives_truncate_intact`）。
- `crates/codegen/xai-grok-mcp/src/liveness.rs`：每个 Ready client 一个轮询 watcher，传输关闭时发 `TransportClosed`，会话侧丢弃死 client 并防抖重启。
- `xai-grok-mcp/src/servers.rs`（5.2k 行）+ `oauth.rs`/`elicitation.rs`：OAuth、elicitation，本轮不展开。

### qling 现状
- `src/mcp/registry.ts:124` `truncateMcpResult`：20KB 字节截断 + `meta.truncated`，**全文直接丢弃**，模型无法回查；尾部 `while(...) body.slice(0,-1)` 逐字符回退。
- `src/mcp/client.ts:150` 只取 `type==="text"` 内容，图片等被丢弃。
- `src/mcp/bridge.ts` `mcpToolsToNativeDefinitions`：**所有 MCP 工具一律 `readOnly: true`**；`src/mcp/types.ts` `MCPToolDefinition` 不保留 `annotations`（readOnlyHint/destructiveHint）。`readOnly` 会流入 `pipeline/hooks.ts:575` 的 `ToolHookContext.isReadOnly`（JSON hook 据此判断）。
- `src/pipeline/hooks.ts:224` `PLAN_MODE_HARD_DENY_TOOLS = [bash,bg_kill,subtask,browser_fetch,browser_act]`——**不含 `mcp__*` 与 `use_tool`**，Plan Mode 下有写副作用的 MCP 工具不被硬拒绝（是否放行取决于 permissions.default，默认 `allow`，见 hooks.ts:300）。
- `src/mcp/stdio-transport.ts:53` 进程 close 时标记断开并 reject pending ✔；无自动重启。
- `QLING_MCP_TOOL_EXPOSURE=search` 时走 `search_tool/use_tool` 渐进发现（`src/tools/mcp-catalog.ts`），与书 §4.4 一致 ✔。

- §4.2.3 参数/结果保真：截断丢全文 ✘。

## 5. 会话持久化与恢复

### Grok Build
- `crates/codegen/xai-grok-session-events/`：每会话 `events.jsonl` append-only（`log.rs` `EventWriter::emit`，带 `ts`，写失败只告警一次 `error_logged`）；`types.rs` `Event` 有 TurnStarted/ToolStarted/ToolCompleted/PermissionRequested/Resolved/TurnEnded/Mcp*/Goal* 等，`EVENT_SCHEMA_VERSION="1.0"`；`TurnOutcomeLabel::Interrupted`："Written at session load for a `turn_started` the previous process never closed"。
- `crates/codegen/xai-grok-shell/src/session/interrupted_turn.rs`：`detect_interrupted_turn` 只读 events.jsonl 尾部 256KB（`EVENTS_TAIL_BYTES`），找未闭合 `turn_started`；`model_reminder()` 向模型注入"上一轮被中断，之前工作可能丢失"；`close_events_turn` 追加 `TurnEnded{Interrupted}` 防止重复报告；`INTERRUPTED_MESSAGE` 写明"Committed tool results were kept"。
- `tracker.rs` `EventTracker`：活跃工具记录，取消时上报当前工具。
- `crates/codegen/xai-sqlite-journal/src/lib.rs`：按文件系统选 WAL/TRUNCATE（NFS 上 WAL 会 SIGBUS），`GROK_SQLITE_JOURNAL_MODE` kill-switch，`BUSY_TIMEOUT=5s`、`BUSY_RETRY_BUDGET=10s` 共享截止时间。qling 不用 SQLite（JSON + JSONL），**仅借鉴"共享重试预算"思想**，不建议引入 SQLite。

### qling 现状
- `src/persistence/atomic-json.ts`：tmp+fsync+rename、`.bak` 备份、按路径串行队列 ✔（质量好）。
- `src/session/session-persistence.ts`：整份快照（messages 全量 + activeRun + recoveryState）。
- `checkpointSession` 调用点：`tui/streaming-repl.ts:477`（每轮结束后）、repl/daemon/命令等 16 处——**均在轮次结束后**；轮中崩溃会丢失该轮所有已完成工具结果，重启加载后也**没有"上一轮被中断"标记**。`agent/main-loop.ts:465` 仅当 `recoveryState.status==="recovering"` 才续跑 activeRun。
- `src/execution/run-trace-store.ts`：`~/.qling/runs/<session>/<run>.jsonl` 已有 append-only 的 `run_started/run_completed`（event-bus.ts:32/40）——**具备做中断检测的数据基础**，但无加载时扫描（rg `interrupted` 无结果）。
- `src/runtime/background-tasks.ts`：纯进程内（文件头注释"进程内"），重启即丢；`truncateBytes` 保留**头部** 512KB，长任务尾部错误被丢。
- `src/mission/manager.ts:28` `init()→loadMissions()` 原样加载，**未对 `running` 状态的 mission 做所有者/存活对账**，进程崩溃后会一直显示 running（需 Pi 确认有无其他对账路径）。

### 书本清单
- §5.1.5 故障分层：控制流层"中断后状态不明"——Grok 用显式 Interrupted 标签 + 模型提醒；qling ✘。
- §5.1.5 "完整性监控……自动修复配对关系"：第 1 轮 history-repair 已覆盖；本轮补"轮中持久化"使修复有东西可修。

### 可借鉴

2. **mission 启动对账**（中/低）：`running` 且无存活 owner → `blocked`/`interrupted` + 事件。→ Brief 06
3. 后台任务输出保留头+尾（中/低）：头 64KB + 尾 448KB。→ Brief 06
4. 后台任务元数据落盘（中/中，round 3）。
