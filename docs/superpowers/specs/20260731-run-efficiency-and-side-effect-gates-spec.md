# 轻灵运行效率与副作用门禁规格

## 需求

- 在不削弱用户规则和验证义务的前提下，减少 system prompt 重复内容、无效工具重试和连续自动压缩。
- 工具参数变化但失败原因相同，也必须计入同类失败预算；同类失败最多允许一次有意义回退。
- 每轮成功的 `write` / `patch` 文件变更必须进入运行时副作用台账，最终答复前持续对模型可见。
- 简单任务不得因失败重试造成几十次 attempt、数十万 token 或大量临时脚本残留。

## 基线证据

2026-07-31 最新本机任务“恢复燕云十六声图标”：

- 总耗时约 453 秒。
- 35 次 attempt、48 次工具启动、20 次工具失败。
- 41 次 bash，其中19次失败。
- 12 次上下文压缩、session token 296024。
- 创建 `probe.ps1` 与 `fix_yysls_icon.ps1`，最终答复只披露后者。
- 强制规则正文同时出现在 system prompt 的直接规则块、静态 RULES section 和 synthetic dynamic message 中。

## 状态与数据流

1. system prompt 仅保留一份完整强制规则；dynamic message 只携带短引用和动态上下文。
2. 每次工具完成后生成结构化观察：工具名、成功/失败、归一化失败指纹、目标文件及创建/更新类型。
3. 运行效率守卫累计观察：
   - 同工具同失败指纹达到2次时暂停。
   - 单次运行工具失败总数达到8次时暂停。
4. 成功文件写入进入去重台账；下一次模型调用前，以合成消息注入完整副作用列表。
5. 自动压缩每次运行最多2次，且两次之间至少间隔4个 Agent turn。
6. 命中守卫时返回可恢复暂停，不继续消耗模型与工具预算。

## 验证

- 纯函数测试覆盖失败指纹归一化、参数变化但错误相同的熔断、总失败预算、压缩预算和副作用去重。
- system prompt 测试确保完整规则仅出现一次，dynamic 引用不复制正文。
- tool orchestrator 测试覆盖创建/更新文件观察。
- main loop 测试覆盖守卫暂停、台账注入和压缩次数上限。
- 串行执行定向测试、构建、完整单元测试、smoke/eval、打包、依赖分层和 `git diff --check`。

## 失败处理

- 守卫暂停时保留工具结果与副作用台账，用户可用 `/recover edit|cancel` 调整任务。
- 失败指纹缺失时使用工具名、错误代码、类别和输出首行的归一化组合，禁止仅按命令参数判断。
- 压缩达到预算后继续保留当前上下文；若 provider 因上下文过大失败，交由现有 provider recovery 处理，不循环压缩。

## 隐私与安全

- 台账只记录文件路径与创建/更新类型，不记录文件正文、凭据或工具输出。
- bash 的不透明副作用不猜测；基座继续要求模型披露实际命令产生的其他副作用。
- 不自动删除临时文件，不扩大现有写入权限。

## 成功标准

- 同类失败最多执行两次后暂停。
- 单次运行自动压缩不超过2次。
- 完整强制规则不再三重注入。
- 所有成功 `write` / `patch` 目标均进入模型可见台账。
- 现有成功任务、恢复、审批、TUI 和非交互输出行为不回归。
