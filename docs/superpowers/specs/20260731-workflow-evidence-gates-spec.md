# 轻灵流程证据门禁与运行状态收口规格

## 需求

- 加强轻灵基座任务流程，使“已确认、可运行、已登录、已连接、成功、最新、实时”等当前状态结论必须由本轮直接证据支撑。
- 明确区分三类证据：文档或 Skill 描述的能力、本机当前运行状态、本次任务实际结果。前一类不得替代后一类。
- 当前可用性与任务有关且存在安全的只读探测时，轻灵应主动执行版本、列表、诊断、身份、状态或帮助命令，不为只读取证额外询问。
- 使用外部工具后，交付应包含实际命令、观察结果与成功判据；证据不足时必须缩小结论。
- 清理临时文件仍属于删除，未获授权时不得以“收尾”为理由执行。
- 成功运行必须清除恢复中的活动状态，防止会话快照在 `run_completed=succeeded` 后仍保存 `recoveryState.status=running`。

## 涉及资源

- `src/pipeline/sections.ts`：基座工作流与证据门禁。
- `src/execution/recovery-controller.ts`：运行终态收口。
- `src/agent/main-loop.ts`：在所有非暂停终态同步恢复状态。
- `tests/unit/opencli-skill-routing.test.mjs`：基座提示词约束回归。
- `tests/unit/execution-recovery.test.mjs`：控制器终态回归。
- `tests/unit/main-loop.test.mjs`：真实外层循环状态回归。

## 状态与数据流

1. 接收任务后先判断结论是否涉及“当前状态”。
2. Skill、文档、记忆只建立“能力说明”；若要断言当前可用，执行同轮只读探测。
3. 最终答复前建立内部的“声明 → 证据”对应关系；没有直接证据的声明降级为文档范围结论。
4. 外层 Agent 循环启动恢复状态并执行任务。
5. `paused` 保留活动运行和恢复状态；`succeeded` 清除恢复状态；`failed`、`exhausted`、`canceled` 写入对应终态并清除活动运行。
6. 会话快照读取收口后的状态，因此成功任务不再残留 `running`。

## 验证

- 提示词单测覆盖证据分层、同轮直接证据、只读探测、声明证据账本、OpenCLI 预检与删除授权。
- 恢复控制器单测覆盖成功清除、失败和取消终态。
- 外层循环单测覆盖成功后恢复状态为空、暂停状态仍可恢复。
- 串行运行定向测试、`npm run build`、`npm run ci:check` 与 `git diff --check`。

## 失败处理

- 只读探测不可用时，报告命令、错误或缺失条件，不将文档描述升级为运行态结论。
- 终态同步不得覆盖 `paused`，以免破坏 `/recover`。
- 验证失败时只修复本次范围内问题；保留当前工作树中的 Dashboard/TUI 用户改动。

## 隐私与安全

- 只读预检不得输出令牌、Cookie、密码或完整敏感配置。
- 外部写入、发布、推送、登录、删除和覆盖仍需明确授权。
- 不新增遥测或远程依赖。

## 已确定的实施决策

- 成功状态通过清除 `RecoveryController` 状态表达，而不是扩展为可恢复的 `succeeded` 状态。
- 失败、耗尽和取消保留终态用于诊断，但不再冒充活动运行。
- 本轮只实施基座约束和状态机修复，不改 Agent 业务工具与 TUI 布局。
